# 渠道售价同步：人工采购价优先与成本利润率设计

## 背景

渠道经营观察主表已经使用渠道内人工维护的采购价，但“同步售价”弹窗会在渠道标记为 Models.dev 来源时绕过人工采购价，重新读取 Models.dev 基础价和分档价。结果是主表与弹窗显示不同成本，点击“应用售价”还可能把人工维护的统一高档采购价覆盖回“基础价 + 上下文分档”。

当前输入项名为“目标加价率”。它的计算口径其实是 `(售价 - 成本) / 成本`，数值可以超过 100%，但名称不利于经营者理解。

## 目标

1. 人工维护采购价是售价同步的最高优先级真源。
2. 人工采购价为统一价格时，弹窗不得重新引入 Models.dev 上下文分档。
3. 输入项改为“目标成本利润率（利润 ÷ 成本）”，保留超过 100% 的设置能力。
4. 预览继续展示毛利额和毛利率，明确区分成本口径与销售收入口径。
5. 应用统一售价时，能够安全地把既有分层计费切换为普通倍率计费。

## 术语与公式

- 成本利润率：`(售价 - 成本) / 成本 × 100%`，允许大于 100%。
- 毛利率：`(售价 - 成本) / 售价 × 100%`；成本非负时不超过 100%。
- 目标售价：`成本 × (1 + 目标成本利润率 / 100)`。
- 示例：成本为 1、售价为 5.56 时，成本利润率约为 456%，毛利率约为 82%。

界面输入项使用“目标成本利润率（利润 ÷ 成本）”。辅助说明固定展示：“100% 表示售价为成本 2 倍；455.56% 表示售价约为成本 5.56 倍。”

## 取价优先级

售价同步按以下顺序选择成本：

1. 渠道存在完整的人工采购价：使用人工采购价。
2. 没有人工采购价，但存在有效探测价：使用探测价。
3. 没有前两者，且渠道明确使用 Models.dev：读取 Models.dev 官方价格与渠道倍率。
4. 仍无完整价格：禁用“应用售价”，展示缺少采购价的错误提示。

人工采购价一旦命中，即使渠道保留 Models.dev 来源标记，也不得再发起官方价同步计划，不得生成官方上下文分档。

## 弹窗行为

### 人工采购价

- 成本卡片显示“使用人工维护采购价”。
- 输入、输出、缓存读取、缓存写入均来自经营观察接口返回的人工价。
- 不展示 Models.dev 厂商名称和上下文分层售价。
- 默认目标成本利润率取当前输入、输出两项成本利润率的较小值，保留两位小数。
- 输入必须为有限且不小于 0 的数，不设置业务上限。

### 官方价格兜底

- 仅在没有人工价和探测价时使用。
- 保留现有 Models.dev 基础价、倍率和上下文分层能力。
- 输入项同样使用目标成本利润率，所有分档按同一目标成本利润率计算售价。

### 预览

预览保留三行：售价、毛利、毛利率。输入项表达成本利润率，结果区表达毛利率；两者必须使用完整名称，禁止统称“利润率”。

## 应用售价与原子更新

人工统一采购价路径提交普通倍率售价，并显式声明切换为普通倍率计费。后端在同一事务中：

1. 写入模型输入、输出、缓存读取、缓存写入的销售倍率。
2. 删除该模型旧的分层计费模式和分层表达式。
3. 保留渠道人工采购价不变。
4. 保留其他模型的倍率、计费模式和表达式不变。

官方价格兜底路径继续提交分层计费表达式和 Models.dev 采购价，不改变既有原子写入语义。

### Grok 4.6 最高档统一计费

`grok-4.6` 属于明确例外：即使 Models.dev 返回上下文分档，也统一取上下文阈值最高档（当前为 ≥200K）的输入、输出、缓存读写作为全量采购价，不创建动态分层售价。

- 弹窗成本、默认目标成本利润率和售价预览均使用最高档采购价。
- 提交时将最高档采购价原子保存为该渠道的统一人工采购价，同时显式切换普通倍率计费并删除旧分层模式/表达式。
- 模型列表不再显示动态计费；再次打开弹窗时按已保存最高档采购价反算，输入 5000% 并应用后仍显示 5000%。
- 其他模型继续遵循原有官方分档兜底规则，不受此例外影响。

## 校验与错误处理

- 成本利润率为空、负数、NaN 或无穷大时禁用提交。
- 人工采购价必须包含输入、输出、缓存读取、缓存写入四项；缺失时不得降级为零。
- 成本输入必须大于 0；输出和缓存成本允许为 0。
- 目标成本利润率导致计算溢出时禁用提交。
- 从分层计费切换为普通倍率计费必须显式请求，旧客户端未携带切换标记时继续保持原有拒绝行为。

## 测试设计

### 前端单元测试

- 人工采购价优先于探测价和 Models.dev 标记。
- 人工采购价路径不生成官方分档计划。
- 成本利润率 0%、100%、455.56% 分别得到成本 1 倍、2 倍、5.5556 倍售价。
- 负数和非有限值被拒绝；大于 100% 的有限值被接受。
- 默认值取输入、输出当前成本利润率的较小值。

### 前端交互测试

- Sol 人工价为 3/13.5 时，弹窗成本显示 3/13.5，不显示 1.5/9 或 272K 分层。
- 输入项显示“目标成本利润率（利润 ÷ 成本）”及倍数说明。
- 提交人工统一价时发送普通倍率计费切换请求。
- 官方价缺少人工维护值时仍能显示并提交分层计划。
- Grok 4.6 使用 ≥200K 最高档统一采购价，5000% 提交普通倍率且重开仍为 5000%，不显示上下文分层。

### 后端单元与集成测试

- 显式切换普通倍率计费时，可从既有分层计费模型切换成功。
- 同一事务写入倍率并删除该模型的分层模式与表达式。
- 其他模型配置不受影响。
- 未显式请求切换时，既有“分层模型不能同步倍率售价”保护保持不变。
- Grok 4.6 的最高档统一采购价与普通倍率在同一事务写入；失败时两者同时回滚。

## 非目标

- 不自动修改生产采购价或当前售价。
- 不改变渠道倍率、模型路由、日志或历史财务数据。
- 不重构渠道经营观察之外的定价页面。

## 验收标准

1. 生产同类数据下，Sol 弹窗成本与主表一致显示 3/13.5、缓存 0.3/3.75。
2. 弹窗不再显示 272K 分层售价。
3. 目标成本利润率允许 455.56%，并给出约 5.56 倍售价。
4. 应用后模型使用统一售价，人工采购价保持不变。
5. 前端单元/交互测试、后端单元/接口测试、类型检查、lint 和生产构建全部通过。
